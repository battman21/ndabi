# NDABI canonical MongoDB profile v0.1

Status: implemented adapter with an accepted Docker campaign.

## 1. Purpose

Execute one bounded MongoDB identifier-window query through the canonical NDABI execute-handle frame.
Retain the fused one-command behaviour from the accepted v5.7 research campaign.

## 2. Authority binding

Bind the frame to MongoDB, the identifier-window profile, the schema, the policy, and the prepared query plan.
Keep the database, collection, fields, command, projection, sort, and limit outside agent-controlled bytes.

## 3. Execution

Accept one first identifier, item count, and positive stride.
Limit the operation to 128 identifiers and the registered one-million-row dataset.
Refuse inadequate row and byte budgets before database execution.
Apply a fixed field projection, ascending identifier order, one batch, a negative limit, and the authenticated deadline.
Write each canonical row directly into the bounded result buffer.

## 4. Boundaries

The adapter is implemented and unit-tested.
The canonical v6.0 Docker campaign passed five fresh processes.
The profile does not support commands, pipelines, writes, arbitrary collections, or general MongoDB access.
